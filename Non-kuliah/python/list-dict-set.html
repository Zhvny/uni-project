TL;DR

  • list: urutan, akses indeks \(O(1)\), cari \(O(n)\).
  • dict: pemetaan key → value, cari key \(O(1)\).
  • set: kumpulan unik, membership \(O(1)\).
  • Butuh urutan → list; butuh pemetaan → dict; butuh keunikan → set.
  • Dedup & membership cepat selalu lewat set/dict, bukan list.

Konsep inti

List: urutan yang bisa diindeks

List adalah kumpulan yang terurut dan boleh punya duplikat; setiap elemen punya posisi (indeks) mulai dari 0. Akses lewat indeks \(O(1)\), tetapi mencari sebuah nilai harus memindai sampai ketemu, yaitu \(O(n)\).

Penting karena list adalah struktur default saat urutan dan perubahan dinamis dibutuhkan: menambah di akhir, menyisip, mengurutkan.

Miskonsepsi: `x in list` untuk list besar sering dipanggil; itu \(O(n)\) tiap kali, jadi loop yang menyisir list berulang bisa jadi lambat.

Dict: pemetaan key → value

dict menyimpan pasangan key-value dan mencari nilai lewat key dengan hash, sehingga rata-rata \(O(1)\). Sejak Python 3.7 urutan penyisipan tetap dipertahankan.

Penting karena dict mengubah "cari di mana" dari pemindaian menjadi lompatan langsung; ini dasar dari tabel lookup, cache, dan menghitung frekuensi.

Miskonsepsi: urutan dict bukan berarti bisa diakses lewat indeks angka; `d[0]` mencari key `0`, bukan elemen pertama.

Set: kumpulan unik

set adalah kumpulan tanpa duplikat dan tanpa indeks; anggotanya harus hashable. Cek keanggotaan rata-rata \(O(1)\), jadi set ideal untuk membership dan deduplikasi.

Penting ketika pertanyaannya hanya "apakah X ada?" atau "berapa nilai unik?", bukan "di posisi berapa".

Miskonsepsi: set tidak terurut, jadi `set[0]` error; untuk urutan tetap pakai list atau `dict.fromkeys` (yang menjaga urutan).

Rumus

Kompleksitas rata-rata pencarian (look-up):

$$ \text{list}: O(n) \quad \text{dict/set}: O(1) $$

SimbolArti
\(n\)Jumlah elemen
\(O(1)\)Waktu konstan (rata-rata)
\(O(n)\)Waktu tumbuh linier

Kapan dipakai: menaksir biaya saat look-up dipanggil berulang di dalam loop besar.

Kapan tidak: operasi sekali jalan pada data kecil; beda \(O(1)\) vs \(O(n)\) tak terasa.

Contoh: mencari 1.000 kali di list 10.000 elemen ≈ \(10^7\) langkah; di set hanya ≈ \(10^3\).

Kode

Operasi umum: akses, tambah, hapus, dan cari.

# list: urutan penting, akses indeks O(1)
buah = ["apel", "jeruk", "mangga"]
buah.append("nanas")        # tambah di akhir
buah.remove("jeruk")        # hapus by value (O(n))
print(buah[0])              # akses indeks -> apel

# dict: key -> value, cari key O(1)
harga = {"apel": 5000, "jeruk": 4000}
harga["mangga"] = 6000      # tambah / ubah
del harga["apel"]           # hapus key
print(harga["mangga"])      # -> 6000

# set: unik, tanpa indeks
seen = {"apel", "jeruk"}
seen.add("mangga")          # tambah
seen.discard("apel")        # hapus (aman bila absen)
print("apel" in seen)       # -> True (O(1))

# cari di list O(n): dipindai satu per satu
print("nanas" in buah)      # -> True

# deduplikasi: set membuang duplikat
kata = ["a", "b", "a", "c", "b"]
print(set(kata))            # -> {'a', 'b', 'c'}

Pola membership cepat dan deduplikasi yang menjaga urutan.

# membership cepat dengan set
ip_terlihat = set()

def sudah_dilihat(ip):
    if ip in ip_terlihat:   # O(1)
        return True
    ip_terlihat.add(ip)
    return False

# dedup sambil pertahankan urutan (dict 3.7+)
def unik_urut(data):
    return list(dict.fromkeys(data))

print(unik_urut(["a", "b", "a", "c"]))
# -> ['a', 'b', 'c']

Apa yang berubah kalau X diubah: menaikkan jumlah elemen \(n\) tidak mengubah cari di dict/set, tetapi memperlambat cari di list.

Latihan mandiri

1. Diberi `angka = [1, 2, 2, 3, 1]`. Bagaimana membuang duplikat dengan satu panggilan, dan apa hasilnya?

Lihat jawaban

Pakai set, mis. `set(angka)` → `{1, 2, 3}`, atau `list(set(angka))` bila hasil harus list. Biayanya \(O(n)\) untuk menyisir sekali.

2. Kenapa `3 in daftar_besar` (list) lebih lambat daripada `3 in himpunan_besar` (set) saat data besar?

Lihat jawaban

List memindai elemen satu per satu, jadi \(O(n)\). Set menghitung hash dan melompat langsung ke posisi bucket, rata-rata \(O(1)\), jadi tak tumbuh dengan \(n\).

Jebakan & FAQ

Kapan list lebih tepat dari dict? Saat elemen cukup diurutkan dan diakses lewat posisi, tanpa label key.

Kenapa set tidak bisa menyimpan list? Karena list tidak hashable (bisa berubah); set butuh hash yang stabil. Pakai tuple sebagai gantinya.

Apakah urutan dict dijamin? Ya sejak Python 3.7; tetapi ini jaminan urutan penyisipan, bukan pengurutan nilai.

Apakah kompleksitas \(O(1)\) selalu benar? Itu rata-rata; pada worst case (banyak hash bentrok) dict/set bisa turun mendekati \(O(n)\).

Kapan dict lebih tepat dari dua list paralel? Selalu, bila data berpasangan label-nilai; dict menghindari risiko list tak sinkron.

Glosarium

Hashable
Objek yang punya hash tetap dan bisa jadi key/anggota set.
Membership test
Cek keanggotaan lewat `in`, mis. `x in set`.
Kompleksitas rata-rata
Biaya tipikal, bukan kasus terburuk.
Deduplikasi
Membuang duplikat sehingga tersisa nilai unik.
Look-up
Mencari nilai berdasarkan key atau posisi.

Checklist kelulusan

  • Bisa pilih list, dict, atau set dari kebutuhan urutan/key/keunikan.
  • Bisa jelaskan kenapa cari di list \(O(n)\) dan di dict/set \(O(1)\).
  • Bisa tulis deduplikasi set dan yang menjaga urutan.
  • Bisa jelaskan syarat hashable untuk key dict dan anggota set.
