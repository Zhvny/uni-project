TL;DR

  • Jaringan merutekan pesan seperti pos: butuh alamat pengirim, alamat penerima, dan isi.
  • Alamat IP memakai bit; IPv4 ditulis desimal bertitik, CIDR menulis rentangnya secara ringkas.
  • Amazon VPC adalah jaringan terisolasi; subnet publik vs privat diletakkan di minimal dua Availability Zone.
  • AWS menyimpan lima alamat IP tiap subnet untuk perutean, DNS, dan manajemen jaringan.
  • Network ACL stateless di tingkat subnet; security group stateful di tingkat instans.

Konsep inti

Jaringan dan perutean

Jaringan adalah cara menghubungkan komputer di seluruh dunia agar dapat berkomunikasi. Menyampaikan pesan di jaringan diibaratkan mengirim surat: butuh isi surat di dalam amplop, alamat pengirim, dan alamat penerima.

Di dunia digital, komputer memproses pengiriman pesan dengan cara yang sama. Proses mengarahkan pesan ke tujuan ini disebut perutean.

Miskonsepsi: perutean cukup memakai nama host. Tidak — perutean butuh alamat numerik (alamat IP) agar pesan sampai ke lokasi yang benar.

Alamat IP dan notasi IPv4

Setiap komputer memiliki alamat IP, yaitu kombinasi bit 0 dan 1. Contohnya alamat 32-bit dalam biner: 11000000 10101000 00000001 00011110.

Biasanya alamat ini dikelompokkan per 8 bit (disebut oktet) lalu dikonversi ke desimal yang dipisahkan titik, misalnya 192.168.1.30. Inilah notasi IPv4.

Miskonsepsi: Anda menulis alamat IP dalam biner di AWS. Tidak — notasi sehari-hari memakai desimal bertitik; biner hanya menjelaskan cara bit bekerja.

Notasi CIDR

Untuk menyatakan satu rentang alamat IP, dipakai notasi CIDR: alamat IP awal, garis miring, lalu sebuah angka. Angka itu menunjukkan berapa banyak bit awal yang tetap.

Contoh 192.168.1.0/24: 24 bit pertama tetap, 8 bit terakhir fleksibel. Karena tiap bit fleksibel bisa 0 atau 1, tersedia 256 alamat. Di AWS rentang terkecil adalah /28 (16 alamat) dan terbesar /16 (65.536 alamat).

Miskonsepsi: angka setelah garis miring lebih besar berarti jaringan lebih besar. Kebalikannya — /24 lebih kecil dari /16.

Amazon VPC

Amazon VPC (virtual private cloud) adalah jaringan terisolasi yang Anda buat di AWS Cloud, mirip jaringan tradisional di pusat data.

Saat membuat VPC, tentukan nama, Region (VPC mencakup semua Availability Zone di dalam Region itu), dan rentang IP dalam CIDR. Satu VPC bisa memiliki sampai lima CIDR IPv4: satu primer dan empat sekunder.

Miskonsepsi: VPC terikat pada satu Availability Zone. Tidak — VPC menjangkau semua AZ di Region yang dipilih.

Subnet publik dan privat

Subnet adalah jaringan yang lebih kecil di dalam VPC, mirip VLAN di jaringan on-premises. Saat membuat subnet, tentukan VPC, Availability Zone, dan blok CIDR subnet (harus bagian dari CIDR VPC).

Gunakan subnet publik untuk sumber daya yang harus terhubung internet, dan subnet privat untuk sumber daya yang tidak. Untuk redundansi, buat setidaknya dua subnet di dua Availability Zone.

Miskonsepsi: satu subnet sudah cukup untuk ketersediaan tinggi. Tidak — pakai minimal dua subnet di dua AZ agar ada cadangan saat satu AZ gagal.

IP yang dicadangkan AWS

Agar dapat mengonfigurasi VPC dengan tepat, AWS menyimpan lima alamat IP di setiap subnet untuk perutean, DNS (domain name system), dan manajemen jaringan.

Contoh: VPC 10.0.0.0/22 mencakup 1.024 alamat, dibagi empat subnet /24 berisi 256 alamat. Dari tiap subnet, hanya 251 alamat yang dapat dipakai karena lima dicadangkan.

Miskonsepsi: semua alamat dalam rentang subnet bisa dipakai. Tidak — lima alamat selalu dicadangkan AWS.

Gateway internet dan gateway privat virtual

Internet gateway menghubungkan VPC ke internet, diibaratkan seperti modem. Berbeda dengan modem rumah, gateway internet sangat tersedia dan dapat diskalakan; melampirkannya ke VPC mengaktifkan konektivitas internet.

Virtual private gateway adalah endpoint VPN di sisi Amazon yang dilampirkan ke satu VPC, untuk menghubungkan VPC ke jaringan privat lain. Di sisi Anda, hubungkan customer gateway lalu buat koneksi VPN terenkripsi.

Miskonsepsi: internet gateway dan virtual private gateway sama. Beda — yang pertama ke internet publik, yang kedua ke jaringan privat lewat VPN terenkripsi.

AWS Direct Connect

AWS Direct Connect membuat koneksi fisik yang aman antara pusat data on-premises dan Amazon VPC, memakai kabel serat optik Ethernet standar ke lokasi Direct Connect.

Koneksi ini memungkinkan antarmuka virtual langsung ke layanan AWS publik atau VPC. Lalu lintas tetap berada di jaringan global AWS dan tidak pernah menyentuh internet publik.

Miskonsepsi: Direct Connect sama dengan VPN. Tidak — VPN berjalan lewat internet publik (terenkripsi), Direct Connect memakai link fisik khusus.

Tabel rute utama dan kustom

Tabel rute berisi seperangkat aturan (disebut rute) yang menentukan ke mana lalu lintas dari subnet atau gateway diarahkan. Saat VPC dibuat, AWS membuat tabel rute utama yang mengizinkan lalu lintas antar subnet.

Tabel rute utama tidak dapat dihapus. Subnet yang tidak punya pengaitan eksplisit memakai tabel rute kustom; kaitkan subnet ke tabel kustom bila ingin rute berbeda per subnet.

Miskonsepsi: tabel rute utama bisa dihapus. Tidak — tabel itu permanen; yang bisa diganti adalah pengaitan subnet ke tabel kustom.

Network ACL: stateless di tingkat subnet

Network ACL adalah firewall tingkat subnet yang mengizinkan atau menolak lalu lintas masuk dan keluar. ACL default mengizinkan semua lalu lintas, jadi baik sebagai titik awal.

ACL bersifat stateless: aturan masuk dan keluar dikonfigurasi terpisah. Untuk server web, izinkan masuk port 443 dan keluar rentang 1025-65535 agar respons dapat meninggalkan subnet.

Miskonsepsi: cukup mengatur aturan masuk. ACL stateless — tanpa aturan keluar, respons server dibuat tetapi tidak pernah keluar dari subnet.

Security group: stateful di tingkat instans

Security group adalah firewall virtual untuk instans EC2. Konfigurasi defaultnya memblokir semua lalu lintas masuk dan mengizinkan semua lalu lintas keluar.

Security group bersifat stateful: ia mengingat apakah koneksi dimulai dari instans atau dari luar, lalu mengizinkan respons tanpa mengubah aturan masuk. Buka port (mis. 80 dan 443) agar instans menerima lalu lintas tersebut.

Miskonsepsi: harus membuka port keluar agar bisa membalas permintaan. Tidak — karena stateful, respons otomatis diizinkan.

Isolasi berlapis tanpa VLAN

Pola desain umum: kelompokkan sumber daya ke beberapa tingkat (web, aplikasi, basis data) dan buat security group yang mengatur komunikasi antar tingkat.

Contoh: internet ke tingkat web lewat HTTPS, web ke aplikasi lewat HTTP, aplikasi ke basis data lewat MySQL. Ini berbeda dari on-premises yang mengisolasi grup dengan VLAN; di AWS security group memberi isolasi setara tanpa mengikat ke jaringan.

Miskonsepsi: isolasi grup sumber daya butuh VLAN seperti on-premises. Tidak — security group mencapai isolasi sama tanpa ikatan VLAN.

Rumus

$$ N_{total} = 2^{\,32 - p} $$

$$ N_{pakai} = N_{total} - 5 $$

SimbolArti
\(N_{total}\)Jumlah alamat di satu blok CIDR
\(p\)Panjang prefix (angka setelah /)
\(N_{pakai}\)Alamat yang dapat dipakai

Kapan dipakai: menaksir jumlah alamat yang tersedia saat memilih rentang CIDR VPC atau subnet.

Kapan tidak: tidak memperhitungkan bahwa tiap subnet dirancang minimal /28 dan lima alamat dicadangkan per subnet.

Contoh: prefix \(p = 24\) memberi \(N_{total} = 2^{8} = 256\) alamat; yang bisa dipakai \(256 - 5 = 251\) alamat per subnet.

Kode

AWS CLI — membuat VPC dan subnet publik:

# buat VPC dengan blok CIDR
aws ec2 create-vpc --cidr-block 10.0.0.0/16

# buat subnet di satu Availability Zone
aws ec2 create-subnet \
  --vpc-id vpc-0abc123 \
  --cidr-block 10.0.0.0/24 \
  --availability-zone us-east-1a

Apa yang berubah kalau X diubah: memperkecil prefix subnet (mis. /24 menjadi /28) mengurangi jumlah alamat yang tersedia di subnet itu.

Latihan mandiri

1. Uraikan notasi 192.168.1.0/24: berapa bit tetap, berapa alamat, dan berapa yang dapat dipakai?

Lihat jawaban

24 bit pertama tetap, 8 bit fleksibel. Jumlah alamat = \(2^{8} = 256\). Karena AWS menyimpan lima alamat per subnet, yang dapat dipakai 251.

2. Sebuah subnet dirancang dengan rentang /24. Berapa alamat yang dapat dipakai, dan kenapa tidak 256?

Lihat jawaban

251 alamat. AWS menyimpan lima alamat di setiap subnet untuk perutean, DNS, dan manajemen jaringan.

3. Sebutkan dua perbedaan network ACL dan security group.

Lihat jawaban

Pertama, cakupan: network ACL bekerja di tingkat subnet, security group di tingkat instans EC2. Kedua, sifat: network ACL stateless (aturan masuk dan keluar terpisah), security group stateful (respons otomatis diizinkan).

4. Kenapa server web di subnet dengan network ACL kustom butuh aturan keluar pada rentang 1025-65535?

Lihat jawaban

Karena network ACL bersifat stateless. Port respons bersifat sementara (mis. 1025-65535), jadi tanpa aturan keluar server akan merespons tetapi lalu lintasnya tidak pernah meninggalkan subnet.

5. Kenapa sebaiknya membuat minimal dua subnet di dua Availability Zone?

Lihat jawaban

Untuk redundansi dan toleransi kesalahan. Jika satu Availability Zone gagal, sumber daya di AZ lain tetap tersedia sebagai cadangan.

Jebakan & FAQ

Apakah boleh memakai CIDR lebih kecil dari /28? Tidak. Rentang IP terkecil di AWS adalah /28 (16 alamat), terbesar /16 (65.536 alamat).

Berapa subnet minimal untuk ketersediaan tinggi? Minimal dua subnet yang dikonfigurasi di dua Availability Zone.

Apa beda network ACL dan security group? Network ACL adalah firewall tingkat subnet yang stateless; security group adalah firewall tingkat instans EC2 yang stateful.

Apakah semua alamat di rentang subnet bisa dipakai? Tidak. AWS menyimpan lima alamat di tiap subnet.

Apakah VPC hanya berada di satu Availability Zone? Tidak. VPC menjangkau semua Availability Zone di Region yang dipilih.

Checklist kelulusan

  • Bisa jelaskan perutean lewat analogi pengiriman surat.
  • Bisa bedakan alamat IP biner dan notasi IPv4 desimal.
  • Bisa uraikan notasi CIDR dan hitung jumlah alamatnya.
  • Bisa sebut faktor yang dipilih saat membuat Amazon VPC.
  • Bisa bedakan subnet publik dan subnet privat.
  • Bisa jelaskan kenapa lima alamat IP dicadangkan tiap subnet.
  • Bisa bedakan internet gateway dan virtual private gateway.
  • Bisa jelaskan keunggulan AWS Direct Connect.
  • Bisa bedakan network ACL (stateless) dan security group (stateful).
  • Bisa rancang isolasi berlapis web, aplikasi, dan basis data.
