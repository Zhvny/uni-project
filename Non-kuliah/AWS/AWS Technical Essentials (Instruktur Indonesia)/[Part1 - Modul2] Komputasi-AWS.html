Komputasi di AWS

Pengantar AWS

TL;DR

  • Tiga tipe komputasi: mesin virtual (VM), kontainer, nirserver.
  • Amazon EC2 menyediakan server virtual; AMI menentukan sistem operasi dan konfigurasi; tipe instans ditandai family + generasi + ukuran.
  • Kontainer mengemas kode + dependensi, lebih ringan dari VM karena berbagi kernel host.
  • Orkestrasi kontainer: Amazon ECS (native AWS) dan Amazon EKS (Kubernetes).
  • Nirserver: AWS Fargate (kontainer) dan AWS Lambda (fungsi). Bayar hanya saat dipakai.

Konsep inti

Server dan model klien-server

Server adalah komputer (atau kumpulan komputer) yang terhubung ke internet dan menyajikan konten ke pengguna internet. Server menangani permintaan HTTP dan mengirim respons ke klien mengikuti model client-server. Klien adalah orang atau komputer yang mengirim permintaan.

Penting karena server menyediakan CPU, memori, dan kapasitas jaringan untuk memproses permintaan pengguna. Contoh server HTTP: IIS (Windows), Apache HTTP Server, Nginx, dan Apache Tomcat (Linux).

Miskonsepsi: "server" selalu perangkat keras. Di cloud, server adalah sumber daya komputasi virtual yang dialokasikan sesuai permintaan.

Tiga tipe komputasi: VM, kontainer, nirserver

Mesin virtual mengemulasi server fisik lewat hypervisor, perangkat lunak yang membagi sumber daya perangkat keras fisik menjadi satu atau beberapa VM. Kontainer mengemas kode beserta dependensinya agar andal berjalan di platform apa pun. Nirserver menghilangkan pengelolaan server sama sekali.

Penting karena tidak ada satu layanan yang cocok untuk semua kasus. Kuncinya memahami penawaran tiap opsi agar arsitektur sesuai kasus penggunaan.

Miskonsepsi: VM akan hilang digantikan kontainer. Tidak. VM menawarkan kekuatan penuh sebuah sistem operasi — instalasi paket, kernel khusus — yang tidak selalu bisa digantikan kontainer.

Amazon EC2 dan hypervisor

Amazon Elastic Compute Cloud (Amazon EC2) adalah layanan web yang menyediakan kapasitas komputasi aman dan dapat diubah ukurannya di cloud. Anda menyediakan server virtual yang disebut instans EC2. Di balik layar, AWS mengoperasikan mesin host dan lapisan hypervisor serta menginstal sistem operasi tamu (guest OS).

Penting karena EC2 adalah dasar yang dipakai beberapa layanan komputasi AWS lain. Untuk membuat instans, tentukan spesifikasi perangkat keras (CPU, memori, jaringan, penyimpanan) dan konfigurasi logis (jaringan, firewall, autentikasi, sistem operasi).

Miskonsepsi: Anda memasang sistem operasi dari nol. Tidak. Instalasi OS bukan tanggung jawab Anda; OS sudah tertanam di dalam AMI yang Anda pilih.

Amazon Machine Image (AMI)

AMI adalah template peluncuran instans: berisi sistem operasi, pemetaan penyimpanan, tipe arsitektur, izin peluncuran, dan aplikasi yang sudah terinstal. Hubungannya seperti resep dan kue: instans EC2 adalah perwujudan langsung dari resep bernama AMI.

Penting karena AMI dapat digunakan ulang. Setelah mengonfigurasi satu instans, Anda bisa membuat AMI darinya dan memakainya untuk meluncurkan instans lain dengan konfigurasi identik. Sumber AMI: Quick Start (buatan AWS), AWS Marketplace, My AMI, AMI komunitas, dan image kustom (EC2 Image Builder). Setiap AMI punya ID berawalan ami- yang berbeda tiap Region.

Miskonsepsi: satu ID AMI berlaku global. Tidak — ID AMI berbeda-beda untuk tiap AWS Region.

Tipe instans EC2

Tipe instans adalah kombinasi vCPU, memori, jaringan, dan kadang penyimpanan instans atau GPU. Nama tipe seperti c5n.xlarge bisa diuraikan: c = family (compute optimized), 5 = generasi kelima, n = atribut tambahan (penyimpanan NVMe lokal), xlarge = ukuran.

Penting karena tiap family dioptimalkan untuk beban kerja berbeda.

FamilyCocok untuk
Tujuan umumServer web, repo kode
KomputasiBatch, HPC, media
MemoriBasis data, cache
TerakselerasiML, grafik, HPC
PenyimpananNoSQL, gudang data
HPC dioptimalkanSimulasi, deep learning

Miskonsepsi: ukuran instans hanya soal CPU. Banyak pilihan ditentukan oleh rasio memori atau kebutuhan GPU, bukan sekadar jumlah vCPU.

Lokasi instans: VPC dan Availability Zone

Kecuali ditentukan lain, instans EC2 ditempatkan di dalam virtual private cloud (VPC). VPC default praktis untuk memulai cepat, tetapi sumber daya di dalamnya bersifat publik dan dapat diakses internet — jangan menaruh data pelanggan di sana. Instans berada di Availability Zone (AZ) pilihan Anda.

Penting untuk ketersediaan tinggi: gunakan minimal dua instans di dua AZ terpisah. Jika satu dari sepuluh instans gagal, hanya 10 persen armada hilang; jika frontend hanya satu instans dan gagal, aplikasi mati.

Miskonsepsi: VPC default aman untuk produksi. Tidak — sumber dayanya publik; pindah ke VPC kustom untuk data sensitif.

Kontainer: kenapa lebih ringan dari VM

Kontainer adalah unit terstandardisasi yang mengemas kode beserta dependensinya dalam lingkungan independen, sehingga dapat dibawa dari pengembangan ke produksi atau dari on-premises ke cloud. Docker adalah runtime kontainer populer yang menangani isolasi, jaringan, dan penyimpanan.

Bedanya dengan VM: kontainer berbagi sistem operasi dan kernel dengan host, sedangkan setiap VM membawa salinan OS sendiri. Kontainer lebih ringan dan mulai hampir instan — penting saat aplikasi harus penskalaan cepat saat lonjakan I/O.

Miskonsepsi: kontainer selalu lebih baik. VM tetap unggul saat butuh kernel khusus atau kontrol penuh atas sistem operasi.

Orkestrasi kontainer: Amazon ECS dan Amazon EKS

Satu instans yang menjalankan beberapa kontainer sulit memberi ketersediaan dan skalabilitas tinggi. Layanan orkestrasi menangani penempatan kontainer, penanganan kegagalan, dan pemantauan. AWS menawarkan dua: Amazon ECS (native AWS) dan Amazon EKS (Kubernetes).

Di Amazon ECS, kontainer dapat dijalankan pada klaster instans EC2 yang Anda kelola (perlu agen kontainer ECS terinstal) atau pada infrastruktur nirserver AWS Fargate. Istilah kontainer berbeda: ECS menyebutnya task dan menjalankan mesin container instance; EKS menyebutnya pod dan menjalankan worker node.

Miskonsepsi: ECS menjalankan Kubernetes. Tidak — ECS memakai teknologi asli AWS; EKS yang menjalankan Kubernetes.

Nirserver: AWS Fargate

AWS Fargate adalah mesin komputasi nirserver khusus kontainer. Fargate mengabstraksi instans EC2 sehingga Anda tidak mengelola infrastruktur yang mendasari, tetapi tetap memakai konsep, API, dan integrasi Amazon ECS yang sama. Fargate mendukung arsitektur Amazon ECS dan Amazon EKS serta terintegrasi dengan IAM dan Amazon VPC.

Penting karena developer dapat fokus mengembangkan aplikasi; Fargate mengalokasikan komputasi tepat seperlunya dan menghilangkan kebutuhan memilih instans EC2, kapasitas klaster, dan penskalaan.

Miskonsepsi: Fargate menggantikan ECS atau EKS. Tidak — Fargate adalah lapisan komputasi yang menjalankannya, bukan orkestratornya.

Nirserver: AWS Lambda

AWS Lambda menjalankan kode tanpa menyediakan atau mengelola server. Anda mengunggah kode sumber dalam bahasa yang didukung Lambda, dan Lambda mengurus menjalankan serta menskalakannya dengan ketersediaan tinggi. Empat sifat nirserver: tanpa server dikelola, diskala berdasarkan penggunaan, tidak membayar sumber daya tak terpakai, ketersediaan dan toleransi kesalahan bawaan.

Konsep kuncinya: fungsi (sumber daya yang dipanggil untuk menjalankan kode), pemicu (kapan fungsi berjalan), event (dokumen JSON berisi data yang diproses), lingkungan aplikasi (runtime terisolasi), paket deployment (arsip .zip atau image kontainer), runtime (lingkungan bahasa), dan handler (metode yang memroses event).

Penting karena penagihan hanya berdasarkan jumlah invokasi dan durasi, dibulatkan ke milidetik terdekat. Ini efektif untuk fungsi berdurasi sangat singkat, mis. di bawah 100 md, dan API latensi rendah.

Miskonsepsi: Lambda punya waktu berjalan minimum yang ditagih. Tidak — AWS membulatkan durasi ke milidetik terdekat tanpa minimum.

Kode

AWS CLI — meluncurkan instans EC2:

# luncurkan instans EC2
aws ec2 run-instances \
  --image-id ami-0abcdef1234567890 \
  --instance-type t3.micro \
  --key-name my-key

Definisi tugas Amazon ECS (JSON) — cetak biru kontainer; contoh ini menjalankan Nginx di Fargate:

{
  "family": "webserver",
  "containerDefinitions": [
    {
      "name": "web",
      "image": "nginx",
      "memory": "100",
      "cpu": "99"
    }
  ],
  "requiresCompatibilities": ["FARGATE"],
  "networkMode": "awsvpc",
  "memory": "512",
  "cpu": "256"
}

Handler AWS Lambda (Python) — metode yang menerima event dan context:

def handler_name(event, context):
    # event: dict hasil parsing JSON
    return {"statusCode": 200, "body": "ok"}

Apa yang berubah kalau X diubah: mengubah requiresCompatibilities dari FARGATE ke EC2 memindahkan tugas dari infrastruktur nirserver ke klaster instans EC2 yang Anda kelola sendiri.

Latihan mandiri

1. Uraikan arti nama tipe instans c5n.xlarge bagian per bagian.

Lihat jawaban

c family compute optimized, 5 generasi kelima, n atribut tambahan (penyimpanan NVMe lokal), xlarge ukuran ekstra besar.

2. Apa perbedaan utama cara kerja kontainer dibanding mesin virtual?

Lihat jawaban

Kontainer berbagi sistem operasi dan kernel dengan host, sehingga lebih ringan dan mulai hampir instan. VM membawa salinan sistem operasinya sendiri, sehingga lebih berat tetapi memberi kekuatan penuh sebuah OS (instalasi paket, kernel khusus).

3. Anda ingin menjalankan kontainer yang sudah ditulis untuk Kubernetes tanpa mengelola node sendiri. Layanan AWS mana yang tepat, dan apa istilah kontainernya?

Lihat jawaban

Amazon EKS (Kubernetes terkelola) dengan komputasi AWS Fargate agar node tidak dikelola. Kontainer di EKS disebut pod, dan mesin yang menjalankannya disebut worker node atau node Kubernetes.

4. Kenapa AWS Lambda cocok untuk fungsi yang eksekusinya sangat singkat?

Lihat jawaban

Penagihan Lambda berdasarkan jumlah invokasi dan durasi yang dibulatkan ke milidetik terdekat tanpa waktu berjalan minimum dan tanpa membayar sumber daya tak terpakai. Jadi fungsi di bawah 100 md tetap efisien biayanya.

Jebakan & FAQ

Apakah AMI bisa dipakai di semua Region? ID AMI berbeda-beda per Region; AMI di satu Region tidak otomatis tersedia di Region lain.

Berapa instans EC2 minimum untuk ketersediaan tinggi? Pertimbangkan minimal dua instans EC2 di dua Availability Zone terpisah.

Apakah Amazon ECS hanya jalan di Fargate? Tidak. Tugas dan layanan bisa dijalankan di infrastruktur nirserver Fargate atau di klaster instans EC2 yang Anda kelola (perlu agen kontainer ECS).

Apa beda task dan pod? Task adalah istilah kontainer di Amazon ECS; pod adalah istilah kontainer di Amazon EKS (Kubernetes).

Apakah Lambda perlu disediakan servernya? Tidak. Lambda menjalankan kode pada infrastruktur berketersediaan tinggi tanpa administrasi dari pengguna.

Bagaimana Lambda memicu fungsi? Lewat pemanggilan langsung via API Lambda, atau lewat pemicu yang memetakan event dari layanan AWS lain (mis. panggilan API, item stream atau antrean).

Checklist kelulusan

  • Bisa sebut tiga tipe komputasi: VM, kontainer, nirserver.
  • Bisa jelaskan peran hypervisor dan guest OS di EC2.
  • Bisa jelaskan AMI dan kenapa bisa digunakan ulang.
  • Bisa uraikan nama tipe instans (family, generasi, ukuran).
  • Bisa sebut enam family instans EC2 dan kegunaannya.
  • Bisa bedakan kontainer vs VM (kernel bersama).
  • Bisa bedakan Amazon ECS vs Amazon EKS dan istilah task/pod.
  • Bisa jelaskan Fargate sebagai nirserver untuk kontainer.
  • Bisa sebut konsep kunci dan model penagihan Lambda.
