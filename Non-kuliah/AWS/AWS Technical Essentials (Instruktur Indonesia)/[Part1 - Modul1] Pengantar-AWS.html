TL;DR

  • Komputasi cloud = sumber daya TI sesuai permintaan, bayar sesuai pakai.
  • Tiga model deployment: on-premises, cloud, hybrid.
  • Enam keuntungan: bayar sesuai pakai, skala ekonomi, tanpa menebak kapasitas, cepat & tangkas, hemat biaya, jangkauan global.
  • Infrastruktur global: Region → Availability Zone; edge location untuk cache (Amazon CloudFront).
  • Interaksi via Console, CLI, SDK. Keamanan = tanggung jawab bersama; akses diatur oleh IAM.

Konsep inti

Apa itu komputasi cloud

Komputasi cloud adalah penyediaan sumber daya TI sesuai permintaan dengan harga bayar sesuai penggunaan. Perusahaan tidak lagi memiliki dan memelihara pusat data sendiri; penyedia seperti AWS yang menyediakan dan mengelolanya.

Penting karena tugas repetitif yang tidak membedakan bisnis (memasang VM, menyimpan cadangan) diserahkan ke penyedia, sehingga tim fokus pada hal yang menjadi pembeda.

Miskonsepsi: cloud bukan sekadar "server milik orang lain". Yang berubah adalah model belanja: dari belanja modal di muka menjadi biaya sesuai pemakaian.

Tiga model deployment

On-premises meng-host perangkat keras di pusat data sendiri. Cloud menjalankan semuanya di penyedia cloud. Hybrid menghubungkan sumber daya cloud dengan sistem internal yang sudah ada.

Penting untuk memilih tingkat kontrol, fleksibilitas, dan manajemen yang sesuai kebutuhan. Contoh: lingkungan QA tambahan di cloud bisa dibuat dalam hitungan menit, sementara on-premises butuh membeli dan memasang perangkat keras.

Miskonsepsi: hybrid bukan "cloud setengah jalan". Ini pola sah untuk memperluas infrastruktur organisasi ke cloud sambil mempertahankan sistem lama.

Enam keuntungan komputasi cloud

  • Bayar sesuai penggunaan — hanya membayar sumber daya yang dipakai, bukan investasi penuh yang menganggur.
  • Skala ekonomi besar — gabungan ratusan ribu pelanggan menurunkan biaya variabel.
  • Berhenti menebak kapasitas — naik-turun skala sesuai kebutuhan dengan pemberitahuan singkat.
  • Kecepatan dan ketangkasan — sumber daya tersedia dengan sekali klik, dari hitungan minggu menjadi menit.
  • Hemat biaya — fokus pada pelanggan, bukan menyiapkan dan mengaktifkan infrastruktur fisik.
  • Jangkauan global cepat — deploy ke banyak Region dalam beberapa klik, latensi lebih rendah.

Infrastruktur global: Region dan Availability Zone

Region adalah lokasi geografis tempat AWS meng-host pusat datanya; tiap Region punya nama dan kode, mis. us-east-1 (N. Virginia). Di dalam Region ada klaster Availability Zone (AZ): satu atau lebih pusat data dengan daya, jaringan, dan konektivitas redundan. Kode AZ = kode Region + satu huruf, mis. us-east-1a.

Penting karena Region terisolasi: tanpa izin eksplisit, data tidak direplikasi antar Region. Untuk aplikasi yang selalu tersedia, replikasi workload ke minimal dua AZ agar satu AZ yang gagal bisa digantikan.

Edge location adalah lokasi global tempat konten di-cache (lebih dari 400 lokasi). Amazon CloudFront merutekan tiap permintaan ke lokasi berlatensi terendah, sehingga konten sampai lebih cepat.

Miskonsepsi: memilih Region bukan sekadar soal jarak. Pertimbangkan empat aspek: latensi, harga, ketersediaan layanan, dan kepatuhan data.

Cara berinteraksi dengan AWS

Tiap tindakan di AWS adalah panggilan API yang terautentikasi dan terotorisasi. Tiga jalurnya: AWS Management Console (web), AWS CLI (baris perintah, bisa diskrip), dan AWS SDK (dari kode aplikasi).

Penting karena pemilihan jalur menentukan otomatisasi. Konsol untuk eksplorasi awal; CLI untuk tugas berulang terjadwal; SDK untuk mengintegrasikan aplikasi.

Miskonsepsi: mengubah Region di konsol berarti mengirim permintaan ke Region lain (URL berubah), bukan memindahkan sumber daya yang sudah ada.

Model tanggung jawab bersama

Keamanan adalah tanggung jawab bersama. AWS bertanggung jawab atas keamanan awan (infrastruktur, perangkat keras, perangkat lunak, jaringan yang menjalankan layanan). Pelanggan bertanggung jawab atas keamanan di dalam awan: konfigurasi layanan dan aplikasi, serta keamanan data.

Penting karena tingkat tanggung jawab pelanggan bergantung pada jenis layanan. Layanan infrastruktur (mis. Amazon EC2) menuntut pelanggan mengelola sistem operasi dan platform; layanan terabstraksi (mis. Amazon S3) hanya menuntut pelanggan mengelola data dan aksesnya.

Miskonsepsi: "AWS sudah mengamankan semuanya" salah. AWS mengamankan awan, tetapi salah konfigurasi (bucket terbuka, izin terlalu luas) tetap salah pelanggan.

Pengguna root dan MFA

Awalnya akun AWS punya satu identitas dengan akses penuh: pengguna root, diakses dengan email dan kata sandi. Kredensialnya ada dua: email + kata sandi (untuk konsol) dan kunci akses (untuk CLI/API).

Penting karena root sangat kuat: akses ke semua sumber daya, termasuk penagihan. Praktik terbaik: kata sandi kuat, aktifkan MFA, jangan bagikan, hapus kunci akses root, dan jangan pakai root untuk tugas harian — buat pengguna IAM sebagai gantinya.

Miskonsepsi: nama pengguna + kata sandi saja cukup. Autentikasi faktor tunggal mudah ditebak (rekayasa sosial, bot); MFA menambah lapisan kedua — "sesuatu yang Anda miliki/know" — sehingga satu kebocoran tidak fatal.

IAM: identitas dan izin

Dua istilah kunci. Autentikasi menjawab "Apakah Anda benar Anda?". Otorisasi menjawab "Tindakan apa yang bisa Anda lakukan?". AWS Identity and Access Management (IAM) mengelola keduanya dan memberi tampilan terpusat siapa yang boleh berbuat apa.

Pengguna IAM mewakili orang atau layanan; kredensialnya permanen sampai dirotasi. Grup IAM mengumpulkan pengguna; semua anggotanya mewarisi izin grup (praktik terbaik, skalabel). Kebijakan IAM (policy) adalah dokumen JSON yang menyatakan izin dan dilampirkan ke identitas. Peran IAM (role) memberi kredensial sementara (15 menit–36 jam) dan lebih efisien dirawat daripada banyak pengguna.

Penting karena akses harus terperinci: berikan hanya izin yang diperlukan (prinsip hak istimewa minimal), dan gunakan peran bila memungkinkan alih-alih kredensial jangka panjang.

Miskonsepsi: IAM untuk login pengguna situs web. Bukan. IAM mengamankan akses ke akun dan sumber daya AWS, bukan memberi fungsi masuk/daftar pengguna aplikasi, dan tidak melindungi sistem operasi atau jaringan.

Kode

Tiga jalur interaksi. Console tidak perlu kode; berikut CLI dan SDK.

AWS CLI — mengelola layanan dari baris perintah:

# daftar bucket S3 di akun Anda
aws s3api list-buckets

# jalankan di Region tertentu
aws ec2 describe-instances --region us-east-1

Respons CLI berupa JSON:

{
  "Owner": { "DisplayName": "tech-essentials" },
  "Buckets": [
    { "Name": "aws-tech-essentials" },
    { "Name": "aws-tech-essentials-employee-directory-app" }
  ]
}

AWS SDK (Python, Boto3) — memanggil layanan dari kode:

import boto3

ec2 = boto3.client('ec2')
instances = ec2.describe_instances()
print(instances)

Kebijakan IAM (JSON) — contoh kebijakan administrator:

{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": "*",
      "Resource": "*"
    }
  ]
}

Kebijakan terperinci: tolak akses S3 di luar akun tepercaya.

{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "DenyS3OutsideMyBoundary",
      "Effect": "Deny",
      "Action": ["s3:*"],
      "Resource": "*",
      "Condition": {
        "StringNotEquals": {
          "aws:ResourceAccount": ["222222222222"]
        }
      }
    }
  ]
}

Apa yang berubah kalau X diubah: mengganti Effect dari Allow ke Deny membalik kebijakan — karena itu Deny eksplisit selalu menang.

Latihan mandiri

1. Ada empat aspek untuk memilih AWS Region. Sebutkan dan beri satu contoh singkat masing-masing.

Lihat jawaban

Latensi (pilih dekat basis pengguna, mis. game/IoT), harga (tarif berbeda antar Region), ketersediaan layanan (tak semua layanan ada di semua Region), dan kepatuhan data (regulasi mengharuskan data di wilayah tertentu).

2. Jelaskan perbedaan "keamanan awan" dan "keamanan di dalam awan".

Lihat jawaban

"Keamanan awan" = tanggung jawab AWS: melindungi Region, AZ, pusat data, perangkat keras, sistem operasi host, dan jaringan yang menjalankan layanan. "Keamanan di dalam awan" = tanggung jawab pelanggan: konfigurasi layanan dengan benar, mengamankan dan mengenkripsi data, serta mengatur kontrol akses.

3. Kenapa memakai grup IAM lebih baik daripada memberi izin langsung ke tiap pengguna?

Lihat jawaban

Izin dilampirkan sekali ke grup dan diwarisi semua anggotanya, jadi pengelolaan lebih mudah dan diskalabel. Saat orang berganti peran, cukup pindahkan antar-grup tanpa mengedit izin satu per satu.

Jebakan & FAQ

Apakah IAM berbayar? Tidak, IAM dapat digunakan secara gratis; hanya sumber daya AWS yang dipakai yang ditagih.

Bolehkah pengguna jadi anggota banyak grup? Boleh. Tapi grup tidak boleh menjadi bagian dari grup lain (tidak ada sarang grup).

Apakah kredensial IAM kedaluwarsa sendiri? Kredensial pengguna permanen sampai admin merotasinya. Peran IAM justru memberi kredensial sementara yang kedaluwarsa dalam 15 menit–36 jam.

Apakah pengguna root boleh untuk tugas harian? Jangan. Gunakan root hanya untuk tugas yang memang butuh root, dan buat pengguna IAM untuk tugas sehari-hari.

Apakah data otomatis ada di semua Region? Tidak. Region terisolasi; data tidak direplikasi antar Region tanpa izin dan otorisasi eksplisit.

Apakah AWS mengamankan data pelanggan? AWS mengamankan infrastrukturnya, tetapi pelanggan tetap bertanggung jawab mengamankan datanya sendiri (enkripsi, cadangan, kontrol akses).

Glosarium

Komputasi cloud
Sumber daya TI sesuai permintaan, bayar sesuai pakai.
Region
Lokasi geografis tempat AWS meng-host pusat data.
Availability Zone
Klaster pusat data redundan di dalam satu Region.
Edge location
Titik global tempat konten di-cache untuk latensi rendah.
Kunci akses
ID + kunci rahasia untuk akses terprogram ke AWS.
MFA
Autentikasi multifaktor: butuh dua metode verifikasi atau lebih.
IAM
Layanan pengelolaan akses ke akun dan sumber daya AWS.
Kebijakan IAM
Dokumen JSON yang menyatakan izin (Allow/Deny).
Peran IAM
Identitas berizin sementara yang diambil (di-asumsikan).
SDK
Pustaka untuk memanggil layanan AWS dari kode bahasa tertentu.
Tanggung jawab bersama
Pembagian keamanan antara AWS dan pelanggan.
