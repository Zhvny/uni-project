TL;DR

  • Kontainer = paket ringan berisi aplikasi + dependensinya, terisolasi namun berbagi kernel OS host.
  • Berbeda dari VM: tanpa OS tamu sendiri → jauh lebih ringan dan cepat start.
  • Image = templat read-only; kontainer = instance image yang sedang berjalan.
  • Dockerfile mendefinisikan cara membangun image; docker build lalu docker run.
  • Kontainer adalah fondasi layanan mikro: tiap layanan dikemas dan di-deploy terpisah.

Konsep inti

Apa itu kontainer

Kontainer adalah unit standar perangkat lunak yang mengemas kode aplikasi bersama dependensinya (pustaka, konfigurasi, runtime) sehingga jalan konsisten di mana pun. Isolasi antar-kontainer dilakukan pada tingkat proses.

Penting karena "jalan di mesin saya tapi tidak di server" hilang: image yang sama menghasilkan perilaku yang sama di laptop, server uji, maupun produksi.

Miskonsepsi: kontainer bukan "VM kecil". Kontainer berbagi kernel OS host, jadi tak ada OS tamu penuh di dalamnya.

Virtualisasi dan abstraksi

Virtualisasi VM mengabstraksi perangkat keras: hypervisor menjalankan beberapa OS tamu, masing-masing dengan kernel sendiri. Kontainer mengabstraksi pada tingkat Sistem Operasi: proses diisolasi (namespace, cgroups) tapi memakai kernel host yang sama.

Konsekuensinya: kontainer jauh lebih kecil (megabyte, bukan gigabyte), start dalam detik atau milidetik, dan lebih padat. VM unggul saat butuh kernel berbeda atau isolasi keamanan yang lebih kuat.

Miskonsepsi: kontainer "tidak aman" hanya karena berbagi kernel. Isolasinya kuat untuk sebagian besar kasus, tetapi memang lebih tipis dari VM — jangan menjalankan proses tak tepercaya tanpa pengerasan tambahan.

Kontainerisasi bukan hal baru

Idenya sudah lama: chroot (1979) mengisolasi sistem berkas, lalu namespace (isolasi tampilan sumber daya) dan cgroups (batas pemakaian CPU/memori) di Linux melengkapinya. LXC membungkusnya menjadi "kontainer" penuh.

Penting karena Docker tidak menemukan konsepnya, melainkan membuatnya mudah dipakai: format image standar, registry, dan alur kerja yang sederhana.

Docker sebagai platform virtualisasi

Docker adalah platform untuk membangun, menjalankan, dan mendistribusikan kontainer. Komponennya: Docker Engine (daemon + CLI), image, kontainer, dan registry (mis. Docker Hub, Amazon ECR).

Penting karena Docker menyatukan format image (OCI) dan tooling, sehingga image yang dibuild bisa dijalankan di banyak runtime (Docker, containerd, Podman, Amazon ECS/EKS).

Manfaat kontainer Docker

  • Portabel — image yang sama jalan di mana saja.
  • Ringan — berbagi kernel, tanpa OS tamu.
  • Konsisten — dependensi terkurung dalam image.
  • Cepat — start dalam detik, mudah diskalakan.
  • Efisien — banyak kontainer per host.
  • Terisolasi — kegagalan satu kontainer tak menjatuhkan yang lain.

Image: templat untuk kontainer

Image adalah templat read-only dan immutable yang berisi sistem berkas + metadata aplikasi. Image dibangun berlapis (layer); tiap instruksi menambah satu lapisan yang di-cache.

Penting karena image adalah artefak yang dibagi dan dipromosikan antar lingkungan. Untuk mengubah aplikasi, Anda membangun image baru — bukan mengedit kontainer yang berjalan.

Miskonsepsi: mengubah file di dalam kontainer yang berjalan bersifat sementara. Perubahan hilang saat kontainer dihapus; ubah di Dockerfile lalu build ulang.

Contoh: Dockerfile

Dockerfile adalah berkas teks berisi instruksi berurutan untuk membangun image: basis (FROM), menyalin berkas (COPY), menjalankan perintah saat build (RUN), dan perintah saat jalan (CMD).

Penting karena Dockerfile membuat pembangunan image reproducible: seluruh definisi lingkungan tersimpan sebagai kode (lihat blok Kode).

Image Docker vs kontainer

Analogi kelas & objek: image adalah "kelas" (cetak biru, read-only), kontainer adalah "objek" (instance yang berjalan dengan lapisan tulis sendiri).

Penting karena satu image bisa melahirkan banyak kontainer identik sekaligus — inilah dasar penskalaan horizontal. Kontainer yang dihapus tak mengubah image asalnya.

Manfaat layanan mikro

Layanan mikro memecah aplikasi menjadi layanan kecil yang berdiri sendiri, masing-masing punya siklus rilis dan penskalaan sendiri. Kontainer mempermudah pola ini karena tiap layanan mudah dikemas, dijalankan, dan diganti.

Penting karena tim bisa merilis dan menskalakan bagian yang perlu saja, serta memilih teknologi berbeda per layanan tanpa mengganggu yang lain.

Tradisional vs layanan mikro

AspekMonolitLayanan mikro

Miskonsepsi: layanan mikro selalu lebih baik. Untuk aplikasi kecil, monolit lebih sederhana dan murah; mikro menambah kerumitan jaringan, orkestrasi, dan observabilitas.

Karakteristik layanan mikro

  • Otonom — bisa di-deploy dan diuji sendiri.
  • Terdesentralisasi — data & keputusan per layanan.
  • Berkomunikasi lewat API/jaringan yang terdefinisi.
  • Skala independen per layanan.
  • Batas domain jelas (satu layanan, satu tanggung jawab).
  • Mudah diganti — tidak mengikat teknologi tertentu.

Kode

Dockerfile — templat untuk membangun image:

# Dockerfile
FROM python:3.12-slim        # basis image
WORKDIR /app                 # direktori kerja
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
COPY . .
EXPOSE 8000
CMD ["python", "app.py"]     # perintah saat jalan

Membangun & menjalankan image/kontainer:

# bangun image dari Dockerfile di folder ini
docker build -t aplikasi-saya:1.0 .

# jalankan kontainer di latar, petakan port 8000
docker run -d -p 8000:8000 --name app aplikasi-saya:1.0

# lihat kontainer yang berjalan
docker ps

# masuk ke shell kontainer yang berjalan
docker exec -it app /bin/sh

Apa yang berubah kalau X diubah: mengganti instruksi COPY . . atau RUN menghasilkan lapisan (layer) baru, sehingga build berikutnya membangun ulang dari titik itu ke bawah.

Latihan mandiri

1. Jelaskan beda image dan kontainer dengan satu kalimat masing-masing.

Lihat jawaban

Image = templat read-only (cetak biru) yang berisi aplikasi + dependensi. Kontainer = instance image yang sedang berjalan, dengan lapisan tulis sendiri.

2. Kenapa kontainer start jauh lebih cepat daripada VM?

Lihat jawaban

Karena kontainer tidak menjalankan OS tamu sendiri; ia berbagi kernel OS host dan cukup menyalakan proses terisolasi. VM harus menyalakan seluruh sistem operasi lebih dulu.

3. Apa peran Dockerfile?

Lihat jawaban

Mendefinisikan langkah berurutan untuk membangun image (basis, salin, perintah build, perintah jalan), sehingga lingkungan aplikasi menjadi reproducible dan tersimpan sebagai kode.

4. Kapan monolit lebih tepat daripada layanan mikro?

Lihat jawaban

Saat aplikasi/tim masih kecil: monolit lebih sederhana, tanpa kerumitan jaringan, orkestrasi, dan observabilitas yang ditambah layanan mikro.

Jebakan & FAQ

Apakah kontainer punya OS sendiri? Tidak. Ia berbagi kernel OS host; yang ada di dalam image hanyalah sistem berkas minimal + aplikasi.

Bisakah saya mengubah file di kontainer yang jalan? Bisa, tapi perubahan bersifat sementara dan hilang saat kontainer dihapus. Ubah di Dockerfile lalu build ulang.

Apakah Docker satu-satunya runtime kontainer? Tidak. Docker yang paling populer, tetapi ada containerd, Podman, dan layanan terkelola seperti Amazon ECS/EKS yang menjalankan image standar OCI.

Apakah memakai kontainer berarti harus layanan mikro? Tidak. Aplikasi monolit juga bisa dikontainerisasi; kontainer hanyalah cara mengemas.

Di mana image disimpan? Di registry, mis. Docker Hub untuk publik atau Amazon ECR (Elastic Container Registry) untuk privat.

Pengelolaan banyak kontainer (ECS, EKS, Kubernetes).
